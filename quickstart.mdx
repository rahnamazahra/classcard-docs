Follow this guide to clone the repository, install dependencies, configure your environment, and spin up the backend application.

## Prerequisites

Before starting, ensure you have the following installed on your local machine:

* **PHP** `>= 8.2` (with standard extensions: `pdo`, `mbstring`, `openssl`, `bcmath`, `xml`)
* **Composer** `>= 2.x`
* **Node.js** `>= 18.x` & **NPM**
* **PostgreSQL** or **MySQL** (PostgreSQL recommended for multi-tenant schema support)

---

## Getting Started

<Steps>
  <Step title="Clone the Repository">
    First, clone the Classcard repository from GitHub and navigate into the project directory:

    ```bash
    git clone git@github.com:pixy-group/classcard.git
    cd classcard
    ```
  </Step>

  <Step title="Install PHP & Node Dependencies">
    Install backend PHP packages via Composer, and frontend asset dependencies via NPM:

    <CodeGroup>
    ```bash Composer (Backend)
    composer install
    ```

    ```bash NPM (Frontend)
    npm install
    ```
    </CodeGroup>
  </Step>

  <Step title="Environment Configuration">
    Copy the example environment configuration file to create your local `.env` file:

    ```bash
    cp .env.example .env
    ```

    Open the `.env` file in your editor and update your database credentials and application settings:

    ```ini .env
    APP_NAME=Classcard
APP_ENV=local
APP_KEY=base64:NNaTi3jmTqRQlozCHFhAYK4bB3UDtdCspCt5SdhlX34=
APP_DEBUG=true
APP_URL=http://classcard.test:8000

APP_LOCALE=en
APP_FALLBACK_LOCALE=en
APP_FAKER_LOCALE=en_US

APP_MAINTENANCE_DRIVER=file
# APP_MAINTENANCE_STORE=database

# PHP_CLI_SERVER_WORKERS=4

BCRYPT_ROUNDS=12

LOG_CHANNEL=stack
LOG_STACK=single
LOG_DEPRECATIONS_CHANNEL=null
LOG_LEVEL=debug

# ============================================================================
# DATABASE CONFIGURATION - LANDLORD (CENTRAL) DATABASE
# ============================================================================
# Multi-Tenant Architecture: Schema-per-Tenant with Central Landlord DB
# The 'classcard_central' database stores organization records (organizations table)
# Each organization gets its own schema for complete data isolation
# ============================================================================

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=classcard_central
DB_USERNAME=root
DB_PASSWORD=
DB_CHARSET=utf8mb4
DB_COLLATION=utf8mb4_unicode_ci

# ============================================================================
# SESSION CONFIGURATION
# ============================================================================
# Using database-backed sessions for multi-tenant environments
# Sessions store in 'sessions' table in landlord database
# ============================================================================

SESSION_DRIVER=database
SESSION_LIFETIME=120
SESSION_ENCRYPT=false
SESSION_PATH=/
SESSION_DOMAIN=null

# ============================================================================
# BROADCASTING & FILESYSTEM
# ============================================================================

BROADCAST_CONNECTION=log
FILESYSTEM_DISK=local

# ============================================================================
# QUEUE CONFIGURATION
# ============================================================================
# Using database queue for local development
# Jobs stored in 'jobs' table in landlord database
# ============================================================================

QUEUE_CONNECTION=database
QUEUE_FAILED_DRIVER=database

# ============================================================================
# CACHE CONFIGURATION
# ============================================================================
# Using database cache for local development
# Cache stored in 'cache' table in landlord database
# For production, recommend: Redis, Memcached, or File
# ============================================================================

CACHE_STORE=database
# CACHE_PREFIX=

MEMCACHED_HOST=127.0.0.1

# ============================================================================
# REDIS CONFIGURATION (Optional)
# ============================================================================
# Disabled by default for local SQLite/Database setup
# Enable for production caching and session storage
# ============================================================================

REDIS_CLIENT=phpredis
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
REDIS_PORT=6379

# ============================================================================
# MAIL CONFIGURATION
# ============================================================================
# Using log mailer for local development
# In production: use smtp, mailgun, sendgrid, etc.
# ============================================================================

MAIL_MAILER=log
MAIL_SCHEME=null
MAIL_HOST=127.0.0.1
MAIL_PORT=2525
MAIL_USERNAME=null
MAIL_PASSWORD=null
MAIL_FROM_ADDRESS="support@classcard.test"
MAIL_FROM_NAME="${APP_NAME}"

# ============================================================================
# AWS CONFIGURATION (Optional)
# ============================================================================
# Leave blank for local development
# Configure for S3 storage in production
# ============================================================================

AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
AWS_DEFAULT_REGION=us-east-1
AWS_BUCKET=
AWS_USE_PATH_STYLE_ENDPOINT=false

# ============================================================================
# VITE CONFIGURATION
# ============================================================================

VITE_APP_NAME="${APP_NAME}"

    ```
  </Step>

  <Step title="Generate Application Key">
    Generate a new unique application key for encryption and session security:

    ```bash
    php artisan key:generate
    ```
  </Step>

  <Step title="Run Database Migrations & Seeders">
    Ensure your database server is running, then execute the migrations and seeders to build the landlord/tenant database schemas and load the initial data:

    ```bash
    php artisan migrate
    php artisan db:seed
    ```

    <Warning>
      Always run `db:seed` after `migrate` in a fresh local environment. The seeder populates the organizations, users, and test credentials the login flows depend on. Without it you will get "Organization not found" or invalid-credential errors when signing in.
    </Warning>
  </Step>

  <Step title="Map tenant subdomains to localhost">
    The backend is multi-tenant and resolves the organization from the subdomain of the incoming request. Requests to `127.0.0.1` or `localhost` alone will not resolve to a tenant, so add the tenant subdomains to your hosts file before hitting the app.

    Edit your hosts file (`C:\Windows\System32\drivers\etc\hosts` on Windows, `/etc/hosts` on macOS or Linux — requires admin or `sudo`) and add:

    ```text
    127.0.0.1  beacon.classcard.test
    127.0.0.1  acme.classcard.test
    127.0.0.1  classcard.test
    ```

    You can now reach a tenant at, for example, `http://beacon.classcard.test:8000`.
  </Step>
</Steps>

## Test Credentials

Once migrations and seeders have run, sign in to the seeded **Beacon** organization at `http://beacon.classcard.test:8000` to exercise every login method:

| Method | Identifier | Secret / Notes |
| :--- | :--- | :--- |
| **Email + Password** | `owner@beacon.com` | `password123` |
| **Student ID + PIN** | `STU-BEACON-SCHOOL-001` | PIN `1234` |
| **Phone OTP** | `+1234567890` | In local env, the request response includes a `debug_otp` field with the code. |
| **Magic Link** | `owner@beacon.com` | Response includes a `debug_token` field so you don't need an inbox. |
| **SSO** | Under **More sign-in options** | Provider `google` against the seeded linked identity. |

<Note>
  `debug_otp` and `debug_token` are only returned when `APP_ENV=local`. They are stripped from responses in staging and production.
</Note>
